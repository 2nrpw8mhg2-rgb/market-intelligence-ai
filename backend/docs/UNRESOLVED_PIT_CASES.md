## Resolution requirements

Identity/reuse cases require a dated issuer/security crosswalk with stable identifiers and an effective ticker-history chain. Terminal cases require the legal event type and effective date, delisting reason, and—according to event type—cash/stock/CVR consideration, successor identifier and conversion ratio, or bankruptcy/receivership recovery. Price-blocked cases additionally require entitled daily bars across membership exit and the post-removal horizons. No case should be promoted from this inventory using ticker or company-name similarity alone.

The canonical machine-readable representation is `backend/docs/UNRESOLVED_PIT_CASES.csv`; it contains one row per unique security and all category flags, statuses and 403 fields.
